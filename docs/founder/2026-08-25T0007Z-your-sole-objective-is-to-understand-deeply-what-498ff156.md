The Handoff: Because you are remote, your laptop might be asleep. The ticket sits safely in the queue.

Scenario 2: The Local Flow (Laptop / Synchronous)

Input: You don't need to use Telegram. You can drop a prompt directly into your local terminal (e.g., using Aider) or your IDE.

Isolation (Crucial Step): The Foreman creates a separate Git Branch for every single ticket (e.g., feature/login-lockout, feature/forgot-password).

Execution: It spins up multiple isolated instances of Aider or OpenHands. Each agent operates only within its assigned branch.

Integration: When an agent gets the BDD tests to pass, it commits the code, pushes the branch, and opens a Pull Request (PR) rather than pushing straight to main.

How to Prevent Multi-Agent Chaos
If you run three instances of Aider in the same local directory, they will overwrite each other's files and break your app. Here is how you solve the multi-agent concurrency problem locally:

Rule 1: One Ticket = One Branch. Your Foreman orchestrator must never let agents work on the main branch. Every ticket pulled from the board automatically triggers a git checkout -b before the coding agent is invoked.

Rule 2: Git Worktrees. Instead of just branches, advanced setups use git worktree. This creates separate physical folders on your laptop for the same repository. Agent A works in Folder A on Branch A. Agent B works in Folder B on Branch B. Zero file-locking conflicts.

Rule 3: State Locking. Once an agent picks up a ticket, the Foreman moves it to In Progress and assigns a tag (e.g., @aider-session-1). This prevents two agents from pulling the exact same spec.
