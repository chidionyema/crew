# Which rulings were never implemented — measured 2026-09-02 14:2x UTC

The founder asked "we changed the way of working and it is still slow — what has not been
implemented", and "agents are still doing things we were supposed to have stopped". This is
the measured answer, from disk, not memory. A law without a protocol is a wish (LAW 44);
these are the wishes.

## The root cause, first

**This ledger holds 7 rulings. There are more than 70.** `docs/rulings/` carries R31–R38;
every ruling after R38 — and most before R31 — lives only in one agent's private memory
folder under `~/.claude`, which the founder has twice ordered is the void (R2
say-once-all-ack; "founder records go in company git, same turn — RED LINE"; "estate
context never lives in the claude folder"). A session that never loads that private folder
cannot obey a ruling it has never seen. **That is why stopped behaviour keeps happening:
most rulings physically cannot reach most agents.**

## What IS enforced (for fairness)

dod-guard (DONE needs a receipt), feed-guard (15-minute handoffs), credential-guard,
founder-doc-capture, friction-relay, the estate-state stop hook (it blocked a wrong reply
today), pr-evidence, the shell/python commit standards, rule-guard checkpoints.

**The pattern: every enforced guard polices how agents REPLY. Almost nothing polices what
was DECIDED.** The reply-format layer is finished; the decision layer is prose.

## The one fix that changes the slope

Move every ruling out of the private memory folder into this directory, one file each, in
the R31–R38 format, and make the session-start hook read THIS ledger instead of the private
one. Then a ruling binds every agent, in every harness, from the same git history the
buyer's engineer will read. Until that lands, each new ruling decays the same way.
