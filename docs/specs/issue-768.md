## Constraints every checkpoint inherits

- **Staging cluster only, zero production credentials.** Spec §0 non-goals and §2: "Agents hold
  zero production credentials — enforced at OCI IAM/compartment level, not policy files." No
  checkpoint below is satisfied by anything reaching the production cluster.
- **No merge without the founder's word.** R60: no PR in any repo merges without Chidi's explicit
  word, checkpoint by checkpoint. Green CI and a passing suite are inventory, not done.
- **Every claim verified end to end, automatically.** The founder's own words above. A checkpoint
  is not satisfied by a person reading code; it is satisfied by the named command exiting 0 and
  its output showing the claimed state, run by CI or `crew verify`, never by memory or narration.

## Checkpoints

Each checkpoint below carries the spec's own §17 "Accept" line, turned into named commands. A
checkpoint is done only when every command in it exits 0 against the real staging deployment —
never a mock, never a read of the code.

### CP1 — Spine + measurement (spec §17 Phase 0, §11, §15)
- `otto replay <task_id>` reconstructs an arbitrary completed task end-to-end from JetStream
  alone (no DB side-channel), diffed against the original envelope: exit 0, zero diff.
- `nats stream ls` lists `OTTO_TASKS`, `OTTO_AUDIT`, `OTTO_VERDICTS`, `OTTO_METRICS`, each with the
  retention from spec §4's table.
- `otto eval run --suite core` completes against the 40–60 task corpus and writes a row to
  Postgres (`psql ... -c "select count(*) from eval_runs where suite='core'"` > 0): a baseline.
- `otto inventory --verify-signature` exits 0 in CI: a signed capability-inventory artifact,
  diffed on every deploy (spec §15).
- Network/bandwidth edge case: NATS partitioned mid-publish (outbox relay retries) — task still
  replays with no gap once the partition heals; `otto replay` shows no dropped sequence numbers.

### CP2 — Tool gateway, tiers, sandbox (spec §17 Phase 1, §6, §9, §10)
- `otto redteam run --suite canary` runs the ≥10 canned prompt-injection attacks (spec §10.5):
  every one fails (blocked), exit 0, zero leaks.
- `otto sandbox-test egress --domain <non-allowlisted>` returns `EGRESS_BLOCKED`; a second call
  against an allowlisted domain succeeds — proves default-deny plus the allowlist proxy.
- `otto audit scan-secrets --since 24h` exits 0 with zero matches: no secret material in any
  stream, only handles (spec §6).
- `otto test taint-cap --untrusted-context` shows a task carrying an `untrusted` block has its
  T2/T3 tool calls converted to queued approval cards, never executed directly (spec §10.2).
- Edge case: sandbox Job hits `activeDeadlineSeconds: 330` — result is `SANDBOX_TIMEOUT`, task
  moves to `needs_human`, never silently retried past the cap.
- Network/bandwidth edge case: egress proxy itself unreachable — `code_exec` with
  `allow_network: true` fails closed (`EGRESS_BLOCKED`), never fails open.

### CP3 — Verification Plane (spec §17 Phase 2, §7)
- `otto test verdict --scenario forged` — a forged signature: task never reaches `completed`.
- `otto test verdict --scenario replayed` — a valid verdict for a different `task_id`: task never
  reaches `completed`.
- `otto test verdict --scenario absent` — no verdict published: task stays `awaiting_verdict`,
  never `completed`.
- `otto test prover-write-deny --system <k8s|postgres|object-storage>` for every system the
  prover can read: every write attempt fails, run once per system (spec §7's acceptance test).
- `otto eval run --suite false-success` on the ≥10 engineered false-success tasks: leakage rate
  == 0 (spec §11).
- Network/bandwidth edge case: prover's fresh-sandbox re-run of "code passes tests" times out on
  a flaky model provider mid-verify — result is `fail` (never a silent `pass`), task routes to
  `needs_human`.

### CP4 — Memory + context engine (spec §17 Phase 3, §8, §12)
- `otto eval run --suite retrieval` reports precision@8 >= 0.8 on the retrieval slice.
- A direct insert into `facts` with `provenance = NULL` is rejected by the database constraint
  (`psql` exit non-zero on the insert); `select count(*) from facts where provenance is null`
  returns 0 against the live table.
- `otto memory hygiene --dry-run` fires a stale-fact card and a contradiction-pair card into a
  test Telegram chat (not the founder's), verified by reading the message back via the Bot API.
- `otto test context-budget --compact` shows compaction at 70% budget writes an `episode` row
  (nothing silently dropped) and a subtask gets fresh isolated context, never the parent transcript.
- Network/bandwidth edge case: hosted embedding API and hosted reranker both degrade — `mem_search`
  falls back to Postgres FTS alone rather than hanging past `deadline_s`.

### CP5 — Router + structured outputs (spec §17 Phase 4, §5)
- `otto eval diff --baseline <ref>` shows a recorded per-lane eval delta for a router/prompt
  change (spec §17 Phase 4 accept, P6).
- `otto test budget-guard --lane bulk --exhaust` shows the lane queues and notifies
  (`on_budget_exhausted: queue_and_notify`) rather than silently degrading to a cheaper model.
- Every claim in an `otto eval run --suite core` transcript with an empty `evidence_refs` renders
  `⚠ unverified:` in the Telegram output — checked mechanically against the rendered message, not
  the model's own text.
- `otto eval run --suite core` reports ungrounded-claim rate < 5% (spec §17 Phase 4 accept).
- Network/bandwidth edge case: the `judgment` lane provider returns 5xx/timeout mid-task — router
  retries once per lane policy, then routes to `needs_human`, never silently falls back to a
  different provider outside the configured lane.

### CP6 — Hardening + phone-first polish (spec §17 Phase 5, §13, §14)
- `otto chaos kill-daemon --task <id>` mid-execution: the task resumes from the stream on a fresh
  daemon and completes with no lost tool calls, verified by `otto replay <id>`.
- `otto chaos partition-nats` mid-task: the task retries once the partition heals and completes;
  no event is duplicated or lost (checked against `Nats-Msg-Id` dedupe).
- `otto drill telegram-only-week` runs a scripted week of representative tasks (one per class from
  spec §3) through the Telegram surface only, end to end, with zero direct CLI/DB touches: exit 0.
- The `staging` Flux row's two BLIND infra-facts rows above (doors, drills) are filled: a
  catalogue entity with an HTTPRoute for the gateway, and a `drills/catalogue.yaml` row naming
  `staging`; re-running `bin/idp-ticket-facts staging` shows both rows populated, not BLIND.

### CP7 — Constitution P1–P8 hold under adversarial test (spec §1)
- **P1** no self-certification: orchestrator process has no prover signing key material
  (`otto test key-isolation --process orchestrator` finds zero private-key material); covered
  jointly with CP3's forged/replayed/absent verdict tests.
- **P2** tiered authority enforced at the gateway, never the prompt: `otto test tier-enforcement
  --prompt-override` shows a prompt instructing the model to ignore its tier is blocked at the
  gateway, not by the model declining.
- **P3** measurement-in-turn: `otto eval run --suite groundedness` shows 0 claims whose
  `evidence_refs` do not resolve to a tool call executed inside that same task.
- **P4** everything on the bus: for a random sample of N completed tasks, `otto replay <id>`
  reconstructs each fully from streams alone — 0 tasks with any event missing from JetStream.
- **P5** untrusted content never escalates authority: covered by CP2's taint-cap test plus a
  dedicated canary in the red-team suite that attempts escalation via `mem_write` from
  fetched content — fails.
- **P6** evals gate change: CI's branch protection requires the eval-suite check to pass before
  merge on the Otto repo/branch (`gh api repos/.../branches/.../protection` lists the eval check
  as required).
- **P7** human gate on T3: `otto test t3-action --no-approval` shows a T3 action is refused
  without Chidi's explicit per-action word — no batching, no standing approval accepted.
- **P8** class-level elimination: `otto incident close <id>` without a linked skill/runbook diff
  returns a non-zero exit — an incident cannot close without a systemic fix attached.
