What should the estate's asset catalogue, agent registry and observability actually be built on, given no funds, LAW 19 portability and LAW 34 provider agnosticism?

Decision it fed

Catalogue and inventory go in SQLite, served read-only by Datasette and replicated by Litestream to object storage, roughly $3-6/month on Fly. Instrumentation is OpenTelemetry OTLP with the GenAI semantic conventions, collected by self-hosted Langfuse (MIT core). Agent identity and discovery use A2A Agent Cards at /.well-known/agent-card.json plus MCP for tool access. Infrastructure as code is OpenTofu, not Terraform. Artifacts are OCI with CycloneDX SBOMs. REFUSED: every seat-priced internal developer portal (Port, Cortex, OpsLevel, Roadie, Compass) because a one-founder estate pays per seat for a directory it can write itself; Humanitec, whose CLI and Terraform provider ship no licence file at all, which under LAW 40 test 3 grants nothing; LangSmith and Braintrust, whose exit is a support ticket; anything requiring Kubernetes; and Backstage as a runtime, because its plugin system is mid-migration and the maintenance cost lands on one person.

Findings

Backstage is the reference catalogue but its frontend system migration means a self-hosted instance is a standing maintenance job, so take its catalogue MODEL and not its runtime. Every hosted portal in the survey prices per developer or per service, which is the wrong shape for one founder and six sessions. Humanitec ships no LICENSE file in either its CLI or its Terraform provider, so nothing it produces can be resold. OpenTelemetry now has GenAI semantic conventions and an entities data model, which makes agent traces portable across vendors and is the single largest lock-in escape available. Langfuse's core is MIT and self-hostable; its licence key gates only enterprise features. A2A Agent Cards give agent discovery a published standard, so the agent registry does not need to be invented here. OpenTofu is the fork with a live release cadence after IBM's HashiCorp acquisition and HashiCorp's BUSL licence change.

What does the DORA 2025 research say about AI-assisted delivery that should change how this estate works?

Decision it fed

Two changes. Treat the founder's complaint as the primary platform signal (user-centricity is the strongest reported driver of product quality), which became LAW 36. And stop treating trust in AI output as given: 39.2% of DORA respondents report little or no trust in AI, which is the same instinct behind the founder's 'I don't trust anything you say' and behind THE FOUR HARD RULES. Verification before assertion is not local pedantry, it is the measured industry condition.

Findings

Organisations that prioritise end user experience produce higher quality products and have more productive developers. Trust in AI is the binding constraint on AI leverage, not capability: those who trust generative AI use it more, and 39.2% report little or no trust. Platform engineering shows up as an amplifier, meaning it multiplies whatever the underlying practice already is, good or bad.

How do production agent systems stop an agent asserting false success, so The Architect stops making statements to the founder that are false?

Decision it fed

The Architect truth gate: validate structured claims against the existing verification_evidence.db ledger instead of grading outbound prose; merge-track upstream hermes-agent issue #54722 / PR #54738 which is this exact gate, rather than writing a second one (LAW 3).

Findings

False success is a measured failure class: 44-52% of all failures on tau2-bench, 75.8% on AppWorld, per-model 13-89% (arXiv 2606.09863). Receipt-checking against a runtime-written ledger detects 91% at 4% false positives versus 35% for regex word-lists (arXiv 2603.10060) — the word-list approach this estate already banned as proxy-grading is also the measurably losing one. Deterministic checks first (claim carries an evidence event id that must exist in SQLite with exit 0 and a timestamp after the last mutation), factored verifier model only for what the ledger cannot type. Upstream hermes-agent has the gate in flight: issue #54722, PR #54738.

What experience-accumulation patterns measurably make an agent improve, so maestro and The Architect learn fast with proof?

Decision it fed

Maestro consult-before-escalate: fingerprint each problem, replay the last successful fix for a matching fingerprint before escalating, and a weekly learning receipt to Telegram proving what last week's escalations cost this week. Distill failures as well as successes (ReasoningBank result); promote a fix to a skill only after 2+ successful reuses.

Findings

Distilled strategy memory from successes AND failures beats raw episodic memory: up to +34.2% effectiveness, -16% steps (ReasoningBank, arXiv 2509.25140). Skill libraries reach milestones 8.5-15.3x faster (Voyager). Proof of learning that survives workload drift: a frozen replay set of ~20 real past incidents re-run weekly — solved-count trend is the one metric immune to the workload changing under you. The everyday metrics: repeat-incident escalation rate declining, repeat resolution time versus first occurrence, memory hit rate.
