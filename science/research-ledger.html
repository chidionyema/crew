What should the estate's asset catalogue, agent registry and observability actually be built on, given no funds, LAW 19 portability and LAW 34 provider agnosticism?

Decision it fed

Catalogue and inventory go in SQLite, served read-only by Datasette and replicated by Litestream to object storage, roughly $3-6/month on Fly. Instrumentation is OpenTelemetry OTLP with the GenAI semantic conventions, collected by self-hosted Langfuse (MIT core). Agent identity and discovery use A2A Agent Cards at /.well-known/agent-card.json plus MCP for tool access. Infrastructure as code is OpenTofu, not Terraform. Artifacts are OCI with CycloneDX SBOMs. REFUSED: every seat-priced internal developer portal (Port, Cortex, OpsLevel, Roadie, Compass) because a one-founder estate pays per seat for a directory it can write itself; Humanitec, whose CLI and Terraform provider ship no licence file at all, which under LAW 40 test 3 grants nothing; LangSmith and Braintrust, whose exit is a support ticket; anything requiring Kubernetes; and Backstage as a runtime, because its plugin system is mid-migration and the maintenance cost lands on one person.

Findings

["Backstage is the reference catalogue but its frontend system migration means a self-hosted instance is a standing maintenance job, so take its catalogue MODEL and not its runtime. Every hosted portal in the survey prices per developer or per service, which is the wrong shape for one founder and six sessions. Humanitec ships no LICENSE file in either its CLI or its Terraform provider, so nothing it produces can be resold. OpenTelemetry now has GenAI semantic conventions and an entities data model, which makes agent traces portable across vendors and is the single largest lock-in escape available. Langfuse's core is MIT and self-hostable; its licence key gates only enterprise features. A2A Agent Cards give agent discovery a published standard, so the agent registry does not need to be invented here. OpenTofu is the fork with a live release cadence after IBM's HashiCorp acquisition and HashiCorp's BUSL licence change."]

What open-source tooling should carry the estate's data collection and plumbing, given one laptop, no budget, and a requirement that every dependency permit commercial resale?

Decision it fed

DuckDB + DuckLake v1.0 with a SQLite catalog + plain Parquet + fastjsonschema contracts + ~30 lines of SQL assertions + dlt for the API-shaped sources; SQLite FTS5 kept for transcript search only. Two new dependencies, MIT and BSD-3, zero servers. Rejected dbt-core (alpha v2, solves a team problem we do not have), SQLMesh (protects downstream consumers we do not have), Great Expectations (18 deps for four SQL statements), Meltano (venv-per-tap to read local files), Iceberg (no server-free local write path), and DuckDB fts as the transcript index (its own docs say the index does not update on append). Filed as crew#74.

Findings

["Four candidate tools fail the resale test outright and were disqualified on licence, not on merit: Soda Core relicensed Apache-2.0 to Elastic License 2.0 on 2026-01-27 and its PyPI classifier now reads Proprietary; Airbyte is ELv2 and its abctl installer now brings Docker, kind, Kubernetes, Helm and nginx; Sling is GPL-3.0 with the useful features behind Sling Pro; ingestr is FSL-1.1. ParadeDB pg_search is AGPL-3.0 by deliberate choice and Typesense is a GPL-3.0 server. The dbt Fusion binary is proprietary under dbt Labs' Product Licensing Agreement even though dbt-core is Apache-2.0, and the archived dbt-labs/dbt-fusion repo is still mostly ELv2. Governance: Fivetran completed its dbt Labs merger 2026-06-01, became steward of Great Expectations 2026-05-13, and donated SQLMesh to the Linux Foundation around 2026-03, so dbt, GX and SQLMesh are now all downstream of one commercial parent. DuckLake reached v1.0 in April 2026, MIT, production-ready with backward-compatibility guarantees, catalog in a SQLite file and data in plain Parquet, which satisfies LAW 19 by construction rather than by remembering to run an export drill. The 76k transcripts need byte-offset resumption, which no tool in the field provides: dlt's filesystem source keys on modification time, so a transcript appended to while a session is live is re-read whole and duplicated, and it lists the entire tree before applying the glob."]
